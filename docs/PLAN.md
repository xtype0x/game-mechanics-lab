# Gacha Game Tool 計畫 v0.3

狀態：M2–M4 完成；M5 主要功能完成（待收尾）
最後更新：2026-10-09

## 1. 定位

服務有創意但實作能力有限的台灣小型遊戲開發者：

**瀏覽機制 → 組合 → 調整參數 → 模擬比較 → 試玩 → 匯出／移植**

- **主產品是「機制模擬主控台」**，DEMO 是證明主控台能產出成品的驗證品。
- 以隊伍回合制（弱點擊破型）作為第一個研究範本。
- 程式、介面、DEMO 一律不使用任何原作名稱、角色、圖像或文本；機制卡可記錄研究來源。
- 介面繁體中文；程式碼與識別字英文。

## 3. 四層模型

| 層級 | 定義 | 例 |
|---|---|---|
| 機制元件 | 可組合的規則片段 | 暴擊、防禦減算、韌性、保底計數 |
| 機制工具 | 編輯／計算／觀察機制的主控台面板 | 傷害分解、行動順序模擬 |
| 組合範本 | 已驗證的元件組合與預設參數 | 弱點擊破型回合制 |
| 專案 | 規則＋角色＋敵人＋關卡＋素材 | 可匯出的 DEMO |

### 3.1 相容性
元件以 `requires` / `provides` 宣告能力（如 `time:action-value`、`resource:energy`、`state:toughness`）。組合時靜態檢查，分為：

1. **已驗證**：有範本與測試。
2. **實驗**：可執行，語意與平衡未驗證。
3. **不相容**：缺依賴或衝突，阻止執行並說明原因。

混合來源的組合稱「自訂規則」，不宣稱還原任何原作。

### 3.2 數值修正模型
每個修正值宣告：`bucket`（乘區）、`op`（add / mul / override）、`cap`、`rounding`。
同乘區相加、跨乘區相乘；每一項可在主控台逐層展開。

### 3.3 規則表示法
條件與公式使用 JSON 表示式樹，只允許白名單運算子；不保存任意程式碼。可序列化、驗證、跨語言移植。

## 4. 核心可移植守則（M2 起強制）

未來開發者多使用 Unity（C#）、Godot、Cocos Creator（TS）與各種伺服器語言；且正式營運的抽卡與戰鬥結算應在伺服器執行。因此：

1. `core` 只有純函式：資料進、資料出；不依賴 DOM、Node API、閉包狀態或動態屬性。
2. 數值規則寫進規格：整數優先；浮點運算明確定義取整時機與方式。
3. 亂數使用公開、可逐位元重現的演算法（sfc32／PCG 類），各子系統獨立亂數流。
4. 每個核心模組輸出 **語言無關的 JSON 測試向量**（輸入 → 預期輸出）。
5. 專案檔 JSON，帶 `schemaVersion` 與遷移函式。

### 4.1 交付給開發者的三層

| 層 | 內容 | 跨平台成本 |
|---|---|---|
| 資料 | 角色、技能、卡池、公式設定（JSON） | 零 |
| 規格＋測試向量 | 公式、事件順序、取整規則＋大量預期值 | 低 |
| 實作 | Agent 實作包（generator）或官方參考移植 | 中 |

**測試向量才是可靠移植的核心**：Agent 依規格產生目標語言實作 → 跑測試向量 → 全數通過才算完成。

## 5. 機制模擬主控台

三欄配置：**機制庫｜工作區｜結果面板**，底部為專案列（保存／載入／匯出／種子／規則版本）。

- 改參數即時重算；昂貴計算才需按執行。
- 每個結果可展開到「這個數字怎麼來的」。
- 每次執行記錄種子、參數快照、規則版本，可重現並存為比較基準。
- DEMO ↔ 主控台雙向：試玩中可開側欄改數值、下一場生效；主控台任一模擬可在 DEMO 畫面重播。

## 6. 主線里程碑

### M2：基礎架構＋傷害機制工具
- 架構（最小 M0）：monorepo、CLAUDE.md、規則契約（修正模型、表示式樹、能力宣告、種子亂數）、專案檔格式、主控台外殼與機制庫列表。
- ① 傷害計算與分項檢視；② 乘區組合器。
- 內建 3 種傷害範本：標準乘區型、防禦減算型、弱點擊破型。
- 暴擊期望值與分布；兩組配置 A/B。
- 測試向量輸出。
- **驗收**：範本有獨立預期值測試；不相容組合有原因；保存／載入一致。

### M3：回合戰鬥核心＋戰鬥模擬工具
- 行動值時間軸、事件佇列與同時事件優先序。
- 能量與大招插入；弱點／韌性／擊破；狀態效果（持續、疊層、結算時機）；規則表式敵人 AI。
- 面板：⑤ 行動順序、⑥ 能量資源、⑦ 削韌擊破、⑧ 狀態效果、⑭ 逐步執行與重播、⑮ 批量模擬（進度、取消）。
- **驗收**：同種子同操作同結果；獨立 QA 依規格推算時序案例。
- **完成紀錄**：獨立 QA 只依 docs/spec/battle.md 重寫引擎，4 場自動戰鬥共 844 個事件逐位元一致。追加攻擊／被動觸發未納入 M3，移至 M4 技能編輯器一併設計。

### M4：內容編輯＋完整主控台
- ⑨ 角色、⑩ 技能與目標、⑪ 敵人 AI、⑫ 戰鬥情境／關卡編輯器（表單＋積木條件）。
- ⑯ 任意兩份快照 A/B。
- 兩個範本：弱點擊破型、基礎回合型；一鍵複製。
- 機制庫：分類、標籤、狀態、相容性篩選、詳情頁。
- 原創內容：6 角色、3 普通敵人、1 首領。
- **完成紀錄**：新增被動觸發與追加攻擊（M3 延後項目，規格 battle.md §12）、內容驗證器、專案 schema v3（戰鬥清單、快照、v2→v3 遷移）、兩個專案範本、機制庫時間模型篩選／相容性提示／工具詳情。

### M5：可試玩 DEMO
- 2D 戰鬥畫面、站位、行動序列、HP／韌性／能量、技能操作。
- 程序繪製角色與演出（待機、攻擊、施法、受擊、擊破、倒下、勝利）。
- 3 個短關卡、編隊、簡易升級、獎勵與結算；簡易卡池（固定機率＋硬保底）。
- 偵錯疊層；主控台雙向連結。
- 動畫速度／跳過／減少動態不影響規則。
- 單一 HTML 匯出、離線可玩。
- **驗收**：實際瀏覽器操作截圖；直接開啟 HTML；斷網遊玩；保存載入。

## 8. 工作方式

- 規則核心、契約與主控台架構由主管（Claude）親自撰寫。
- Subagent：研究員（查證）、獨立規則 QA（只看規格）、平行實作（worktree 隔離）。同時最多 3 個，不遞迴，同檔單一寫入者。
- 每個里程碑回報：操作入口、實際測試命令與結果、未測項目、已知限制、可試操作清單。
