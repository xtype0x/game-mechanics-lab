# DEMO 機制模組分類

DEMO 是用來**單獨測試某個機制**的試玩外殼：每個機制都盡量可以拆掉，看看沒有它時遊戲變成什麼樣子。但有些東西拆掉後遊戲就無法進行，所以先把機制分成「骨幹」與「可拆模組」。

資料：`packages/core/src/modules.ts`（`DEMO_MODULES`、`resolveModules`）。向量：`packages/core/vectors/modules.json`。主控台的「DEMO 模組組合」工具可切換模組並即時顯示結果。

> 這份分類會隨著新機制加入而調整。新增機制時：在 `DEMO_MODULES` 加一筆，寫清楚它**提供**與**需要**的能力，再更新下表。

## 1. 能力（capability）
模組之間不直接互相依賴，而是透過「能力」：

| 能力 | 意義 | 必要 |
|---|---|---|
| battle | 能打一場有勝負的戰鬥 | ✔ |
| content | 有要打的關卡／敵人 | ✔ |
| roster | 玩家有角色可用 | ✔ |
| team | 決定誰上場 | ✔ |
| currency | 能賺取與花費資源 | |
| growth | 戰鬥之間能讓角色變強 | |
| gacha | 隨機取得角色 | |

**可遊玩的最低條件：battle、content、roster、team 都有人提供。**

## 2. 分類
### 2.1 骨幹（不能拆）
| 模組 | 提供 | 需要 | 為什麼不能拆 |
|---|---|---|---|
| 回合制戰鬥 | battle | — | 沒有戰鬥就沒有可玩的內容 |
| 關卡 | content | battle | 沒有要打的對象 |

### 2.2 骨幹插槽（必須有人提供，但實作可替換）
這類能力是必要的，但「怎麼提供」本身就是要研究的機制。拆掉某個實作時，內建的預設實作會自動補上：

| 必要能力 | 可拆的實作 | 拆掉後的預設實作 |
|---|---|---|
| roster（角色來源） | 抽卡 | 自由選角：所有我方角色一開始就能用 |
| team（上場隊伍） | 編隊 | 固定隊伍：主控台目前的隊伍（或前 4 人） |

### 2.3 可拆模組
| 模組 | 提供 | 需要 | 拆掉後 |
|---|---|---|---|
| 貨幣與獎勵 | currency | content | 不發獎勵、不顯示錢包；需要貨幣的模組一併停用 |
| 抽卡 | roster, gacha | currency | 角色改為自由選取 |
| 機率公示 | — | gacha | 召喚畫面不顯示機率表 |
| 角色升級 | growth | currency | 所有角色固定 1 級（主控台原始數值） |
| 關卡解鎖順序 | — | content | 所有關卡一開始就能挑戰 |
| 編隊 | team | roster | 改用固定隊伍 |

### 2.4 依賴關係
```
battle ← stages(content) ← economy(currency) ← gacha(roster, gacha) ← disclosure
                         ↖ progression        ↖ growth
roster ← teamEdit(team)
```
例如關掉「貨幣與獎勵」時，抽卡與升級都沒有資源可用，會被自動停用並在工具中說明原因。

## 3. 解析規則（`resolveModules`）
1. 候選＝骨幹模組＋使用者開啟的可拆模組。
2. 反覆移除「需要的能力沒有被其他候選或預設實作提供」的候選；被移除的可拆模組記為「被停用」並列出缺少的能力。
3. 預設實作只有在沒有任何可拆模組提供同一能力時才啟用。
4. 必要能力都有人提供即為可遊玩。

## 4. 不屬於模組的東西
- **演出設定**（AUTO、倍速、跳過、減少動態）：只影響時間，不影響規則，不列為機制。
- **戰鬥內的機制**（擊破、護盾、支配…）：屬於戰鬥規則，在主控台的戰鬥工具中逐一開關與研究，不在這層切換。

## 5. 之後可能調整的方向
- 抽卡以外的角色來源（關卡掉落、商店購買）會成為 roster 的另一個實作。
- 體力、每日任務、裝備等經濟系統加入後，currency 可能拆成多種資源。
- 若加入「多個卡池」或「抽卡也給裝備」，gacha 能力可能細分。
