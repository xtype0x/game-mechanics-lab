## 1. 傷害變體：增幅反應（通過）
火屬性技能觸發「增幅反應」：`×1.5 ×（1 + 2.5 × 精通 /（精通 + 1200））`（原創常數）。

用到的資料擴充點（damage.md）：
- 自訂數值 `customStats`：攻擊方「精通」。
- 自訂旗標 `customFlags`：「觸發增幅反應」（預設開）。
- 自訂乘區 `customSteps`：`if(flags.amplify && skill.element == "fire", …, 1)`，排在增傷之後（order 25）。

驗證：
- 組合、相容性檢查、戰鬥驗證器都沒有錯誤；組合狀態為「實驗組合」（PLAN §3.1：自訂規則）。
- 手算：精通 300 → ×2.25；精通 0 → ×1.5；冰屬性或旗標關閉 → ×1。
- **直接進入戰鬥**：角色數值的「精通」與狀態修正 `stat:mastery`（範例的「熾燃」）都會帶進傷害計算；同種子比較，焰華的傷害為無精通時的 1.5 倍。
- 傷害分項檢視自動出現「精通」欄位、旗標開關與新乘區的逐步展開。
- 新增測試向量 `damage.json` 的 `m6/amplify-fire`、`m6/amplify-flag-off`（字串比較與自訂旗標在乘區中的行為），移植版本因此也能涵蓋。

**意義**：傷害管線的擴充點（表示式樹＋自訂數值／旗標／乘區）足夠表達常見的「條件式乘區」類變體，移植版本不需要任何新程式碼。

## 2. 卡池規則：天井（部分通過）
規則：每累計 200 抽自動獲得一次限定 5★，與 5★ 保底分開計算。

表達方式：在最上層加一個稀有度「天井」：機率 0、硬保底 200、物品為限定角色。因為每抽只擲一次且高稀有度優先（gacha.md §2.2），第 200 抽一定落在天井；天井不重設 5★ 的計數，正好是「分開計算」。

驗證（抽卡規則本身正確）：
- 450 抽中天井恰好出現在第 200、400 抽；第 200 抽前後 5★ 計數只加 1，不會被重設。
- 長期比例：天井恰為 1/200（確定性計數）。

### 發現的限制
1. **精確綜合機率太慢**（gacha.md §3.3）：長期機率要解所有稀有度計數的聯合狀態，天井池為 200 × 90 × 10 = 180,000 種，實測超過 5 分鐘。M1 的 2,000,000 上限只防止記憶體爆量，不防止介面卡死。
   - **已在主控台處理（未改核心）**：狀態數超過 20,000 時，卡池編輯器、機率公示產生器與 DEMO 的機率公示改用 20 萬抽的抽樣估計，並明確標示「抽樣估計」。天井池開啟時間約 0.6 秒。
2. **抽數分析只看第一個稀有度**（gacha.md §3.2）：`targetDistribution` 把天井當成「最高稀有度」，問「多久拿到第一個 5★」會得到「固定 200 抽」。預算模擬器因此無法回答「天井池拿到限定要幾抽」這個最重要的問題。
3. **「主要稀有度」沒有定義**：DEMO 的卡池橫幅、卡片樣式與「距離保底」都假設第一個稀有度就是主角色稀有度，天井池會顯示「天井 機率 0.0%」。

### 為什麼卡池需要核心改動才算真正可擴充
傷害有表示式樹當擴充點；卡池模型（M1）是**固定欄位**：機率、軟硬保底、限定比例、大保底。天井能表達是巧合（剛好可以用「機率 0 的稀有度」模擬）。下列常見規則目前都**無法只用資料表達**：

| 規則 | 需要的能力 |
|---|---|
| 定軌（選定限定角色，歪 N 次必中） | 持久的玩家選擇與計數器 |
| 兌換商店／可選天井（累積點數自選） | 點數資源與兌換動作 |
| 捕獲類（歪多次後提高限定比例） | 依計數改變 `share` |
| 跨池繼承保底 | 卡池群組共用狀態 |
| 首次十連必得 5★、新手池 | 依總抽數的一次性規則 |

## 3. 建議（需要修改核心，請決定是否進行）
1. **卡池擴充點**：讓 `rate`、`share` 可以是表示式（scope：各稀有度計數、大保底旗標、總抽數、自訂計數器），並加入「自訂計數器」與「抽後更新計數器」的資料規則。如此定軌、捕獲類、新手池都能只用資料表達，與傷害管線一致。
2. **分析目標**：`targetDistribution` 改為「任意物品集合」為目標，並在模型中標示「主要稀有度」（解決限制 2、3）。
3. **長期機率的效能**：對「機率 0＋硬保底」這種確定性計數層做分解（它與其他層獨立），可讓天井池回到精確計算；一般情況保留抽樣後備。

這三項都會改變抽卡規格與測試向量（gacha.md 2.0），建議作為下一個獨立里程碑，再重做一次本報告的天井與上表規則，確認全部只用資料即可表達。
